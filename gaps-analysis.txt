1. TypeScript compilation fails with 35+ errors
   ──────────────────────────────────────────────
   Running `tsc --noEmit` produces errors across 11 files. The project cannot
   build. Specific issues:

   (a) persistence/*.ts (database.ts, checkpoint.ts, event-log.ts)
       - Database.run() does not exist on the sqlite-wasm API type.
         The @sqlite.org/sqlite-wasm library's Database type doesn't expose
         `.run()` as expected. Need to align usage with the actual API.
       - SAHPoolUtil.metrics property doesn't exist.

   (b) core/network/swarm.ts
       - connectionEncrypters should be connectionEncryption (libp2p API change).
       - Stream API mismatch: .source.getReader(), .remotePeer, .sink.write
         don't exist on libp2p Stream types (API changed between versions).
       - Return type of async stop() should be Promise<void>.

   (c) core/blackboard/observer.ts
       - Yjs generic constraint: AbstractType<unknown> doesn't satisfy
         AbstractType<any>. Need Y.Map<unknown> or proper Yjs type params.
       - YMapEvent<unknown> is not assignable to YEvent<unknown>[] (typo
         in event handler — expects array but gets single event).

   (d) webllm/profiles.ts
       - GPU, GPUDevice, GPUBufferUsage, GPUAdapter are not available.
         Missing @webgpu/types dependency or tsconfig DOM types.

   (e) Unused variable violations (noUnusedLocals: true):
       - lock.ts:3 — getLocks unused
       - dag.ts:108 — node unused
       - gossip.ts:34 — onMessage unused
       - sync.ts:108 — state unused
       - collector.ts:13 — memory unused

   (f) sync.ts:166 — states.get(nodeId) expects number key, gets string.

   (g) database.ts:36,43 — sqlite-wasm API expects different arg counts.

2. y-webrtc runs in the main thread, contradicting architecture
   ──────────────────────────────────────────────────────────────
   Architecture doc: "The libp2p swarm, Yjs WebRTC sync, and MCP server
   live in a single SharedWorker."

   Implementation: YjsSyncProvider (y-webrtc) is created in src/main.ts,
   NOT in the SharedWorker. This means:
   - WebRTC connections are held in the main UI thread (can freeze UI).
   - The SharedWorker's SwarmNode (libp2p) is never started.
   - Two WebRTC stacks exist (y-webrtc in main thread + libp2p webrtc
     in SharedWorker) but only the main-thread one actually runs.

   Decision needed: either move y-webrtc into the SharedWorker (per
   architecture doc) or accept the current design and update docs.

3. SharedWorker SwarmNode is never started
   ────────────────────────────────────────
   In src/workers/network.shared.ts:
   - `let swarm: SwarmNode | null = null` (line 35)
   - `init()` (line 39) does NOT call swarm.start()
   - The swarm variable is never assigned to at all
   - So libp2p peer discovery, gossip, and MCP streaming do nothing

   Result: All libp2p infrastructure is dead code at runtime.

4. MCPServer instantiated but orphaned
   ────────────────────────────────────
   In network.shared.ts line 33:
   ```
   void new MCPServer();
   ```
   - Instance is not stored → garbage collected.
   - Server has no handlers registered, no MCP stream handling wired up.
   - MCP is a dead code path.

5. No .env file — only .env.example exists
   ───────────────────────────────────────
   The app will try to connect to ws://localhost:4444 by default
   (hardcoded fallback in config.ts), which works only if the
   signaling server is running. But:
   - No .env file is provided so developers can't customize config.
   - .env.example contains no VITE_CORS_PROXY_URL or other optional
     values that are documented as configurable.
   At minimum, .env should exist with defaults that match dev.sh.

6. runInference() is a 15-line stub
   ────────────────────────────────
   src/agents/worker/inference.ts is a placeholder:
   ```
   return { type: 'inference_result', output: `Response to: ${prompt}` };
   ```
   The NodeWorkerAgent in worker.ts does call @webllm/index (chatStream,
   loadModel, etc.) directly — so the main inference path may work.
   But the dedicated inference.ts file is misleading and unused by the
   actual agent flow. Either:
   - Migrate inference logic into inference.ts and have worker.ts call it.
   - Or remove inference.ts if it's vestigial.

7. Synthesizer preview vs final result logic untested end-to-end
   ──────────────────────────────────────────────────────────────
   Architecture describes a two-phase output model:
   - Active workflows show WorkflowPreviewResult (streaming LLM output).
   - Completed workflows show WorkflowResult (synthesizer consolidation).
   The implementation has updateWorkflowPreviewResult() but the
   synthesizer's interaction with it and the UI switching logic
   are not tested together. This is the core user-facing output
   pipeline and has no end-to-end validation.

8. Agent workers may not receive the SharedWorker port correctly
   ──────────────────────────────────────────────────────────────
   In main.ts, finishSharedWorkerConnection() (line 211) uses a 200ms
   setTimeout to defer port transfer. There's no guarantee the
   SharedWorker's onconnect has fired by then. Race condition
   between:
   - SharedWorker.onconnect firing (async)
   - setTimeout(finishSharedWorkerConnection, 200)
   Can miss the port transfer entirely, making all agents silent.

9. No SharedWorker bootstrap peers configured
   ──────────────────────────────────────────
   SwarmNode constructor accepts bootstrapPeers but no actual
   multiaddrs are provided. Peer discovery relies only on y-webrtc
   signaling. The libp2p DHT and bootstrap discovery never run.
